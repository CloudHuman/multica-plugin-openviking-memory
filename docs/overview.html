怎么工作

三层分工与七条连线

Multica 负责发出事件和把工具交给智能体，插件服务负责验签、取材、排队、召回和隔离，OpenViking 负责存储、抽取和检索。插件本身不修改 OpenViking 的实例配置。

  • 1事件：任务完成或失败、新评论（task.completed / task.failed / comment.created），签名投递；接收失败返回 503 供 Multica 重投。
  • 2工具调用：memory-recall / remember / status 和 15 个 ov-* 工具。插件从签名体可信地得知调用者，补丁版还带调用它的运行。
  • 3读取运行详情：运行类型、触发输入和转写。需要任务读取 API（补丁 0001）；stock Multica 上只能以收尾评论代表一次运行。
  • 4归档并提交：写入对应范围的会话再提交，由 OpenViking 异步抽取。每个范围一把 key。
  • 5检索与读取：按当前运行可读的范围并行检索，合并、过滤、去重，返回全文和来源 URI。
  • 6账号级模板：工作区在插件配置里填写抽取规则时，插件把它写进该工作区自己的账号，只影响这个工作区；清空即恢复默认。
  • 7模型调用：抽取、向量和重排都由 OpenViking 自己调用模型服务，插件不经手。
一条记录的去向

从运行结束到下次被召回

这是一次 issue 任务的真实顺序。状态是分开记录的：归档成功不等于抽取完成，抽取完成也不等于已经能检索到。

  1. 运行结束Multica 发出签名事件
  2. 取材读取运行类型、触发输入和转写，去掉平台运行说明
  3. 持久化入队先落盘再应答，重复投递只对应一个作业
  4. 提交到 OpenViking写入该 issue 的任务协作空间
  5. 模型抽取OpenViking 生成实体、事件、偏好等记忆
  6. 监视与重驱失败时把记录放进新会话再抽取，默认最多 2 次
  7. 下次召回新任务开始时 memory-recall 绑定当次运行，带出处返回
  8. 共享晋升夜间把可复用记忆经质量门槛晋升到工作区共享
抽取状态：pendingdoneredrivenfailedtimeout可在 memory-status（本工作区）和 /admin/status（全部）查看。

七类记忆范围

一个工作区对应一个 OpenViking 账号，七类场景各占一个独立用户空间。智能体甲读不到乙的公共记忆，是因为存储层直接返回 403。

范围什么时候写入谁能读需要补丁真实智能体样例
任务协作issue 运行结束、评论（成员算人类反馈，智能体算智能体陈述）在这个 issue 上工作的运行运行转写需要；评论不需要basic、quality、matrix
智能体公共memory-remember、ov-* 写入这个智能体自己不需要basic 主动记忆、matrix
工作区共享夜间晋升可复用类别（经验、案例、偏好、实体）工作区内所有智能体不需要quality：10-02 六轮里 B 都取回了当前事实
私聊配对私聊运行，成员原话按本人归属这个智能体与这位成员需要（chats:read）quality 私聊偏好、matrix 新会话
运行快速创建等单次运行这次运行需要matrix 快速创建
自动化自动化运行（手动、webhook、cron）这个自动化需要matrix 三种触发
委派通道委派交接（@mention 评论）发送方与接收方需要matrix A→B 交接

依赖与边界

原版 Multica 能用什么，补丁补上什么

原版 Multica 开箱可用

  • 评论归档：成员反馈、智能体陈述、插件消息按作者归属
  • memory-recall：可用，但不知道是哪次运行在调用，可由 issue_id 指定
  • memory-remember、memory-status、15 个 ov-* 工具、共享晋升
  • 运行本身不归档：以智能体的收尾评论代表，运行事件以 200 跳过，不触发熔断

补丁 0001–0005（本仓库维护，部署时应用）

  • 0001 任务读取 API：运行转写；私聊、快速创建、自动化、委派归档；召回绑定调用它的运行
  • 0002 daemon 凭据：只有插件工具、没有远程 MCP 时，工具调用不再返回 401
  • 0003 快速创建：关联 issue 后保留原运行类型和成员提示
  • 0004 交付恢复：最终评论已发布但收尾失败时，经成员确认复用已有交付
  • 0005 自我 @：智能体在同一 issue 上 @ 自己时不再派发给自己，跨 issue 的自我通知照常

运行时

  • OpenCode：全部工具可用，本轮真实验证都用它
  • kimi 等 ACP 运行时：需要给智能体登记直连条目，会绕过门面限制
  • pi：Multica 适配器不下发 MCP（multica#8961）
  • Codex：令牌刷新失败，未完成全链路验收
