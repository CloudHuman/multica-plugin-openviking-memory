## 实际模型请求

原生 OpenCode 1.17.7 与 OV 0.4.22 都在现有 SDK 通道记录脱敏请求元数据，凭据、模型、代理与证书信任保持原配置。OV 观测窗口共 743 次请求，SDK 边界缺认证头 0 次，重定向 0 次。状态统计：

```json
{
  "/api/v1/embeddings:401": 244,
  "/api/v1/chat/completions:401": 78,
  "/api/v1/embeddings:200": 317,
  "/api/v1/chat/completions:200": 102
}
```

401 与 200 同时存在；错误请求在 SDK 边界带有认证头，已保留 cf-ray 等请求 ID。不能据此证明中间代理或网关最终收到相同认证内容，最终原因仍待定位。OV 记录来自共享原生实例的观测窗口，不与单个任务一一归因。

> 后续更正：这里的"带有认证头"只表示认证头非空，`Bearer` 加空 token 也计入其中。OpenRouter 只在收到 `Bearer` 加空 token 时返回 `Missing Authentication header`，因此这份数据不能排除客户端发出了空密钥。复核与新增字段见 [auth-401-diagnosis-2026-10-01.md](auth-401-diagnosis-2026-10-01.md)。

该场景由成员直接提供答案，单独计分，不能用来证明蒸馏准确。生产接口要求成员选择完整最终评论与其精确 SHA-256，拒绝跨工作区、私有智能体越权、错误摘要/来源/失败类型及已有后续运行。它不自动把任意评论视为交付。

原有失败保留，继续执行只补齐未做的查询，分母不缩小。查询必须恢复当前金额、消息系统、天数，并引用实际召回的共享 URI。准备阶段失败、检索超时、没有可用语料、最终 JSON 格式错误会分别影响端到端效果，不能把上述比例称为纯蒸馏模型准确率。每个样例和错误见同名 JSON。私聊隔离还要求智能体实际完成召回；未发起工具调用的模型失败只能算未验证。

直接读取共享文件时，三个别名、对应当前金额字符串和消息系统字符串均存在；这只是内容检查，不能证明语义正确或索引可用。第一组同时保留了历史 7600。私聊种子原生运行因 401 失败，但三个目标标题已经完整进入原始归档；抽取重驱后显示 done，配对范围仍有 0 个记忆文件。这是漏提取现象，最终原因还需单独定位，不能把私聊 0/3 全部归因于检索。实际新任务的共享召回多次超过插件 15 秒预算。可用记忆的存在没有转化为稳定的最终答案，只读探针的原生 find 在同范围也超过 15 秒，尚无证据支持仅切换接口能修复。后续应优先解决提供商 401 和检索耗时。
