## 真实执行发现并修复的问题

1. **只有插件工具的运行缺少 daemon 凭据。** 初始真实智能体看到所有工具，但每次调用均返回 401。Multica 原函数只在存在远程 MCP 连接时签发 daemon 凭据，遗漏仅有 HTTP 插件工具的运行。新增 `upstream/multica/0002-fix-plugins-daemon-credential-for-hook-only-tasks.patch`，在存在任一种工具时签发原有范围凭据。回归先失败、修复后通过；覆盖工作区/daemon 范围、有效期、缺少 daemon 身份时拒绝及无工具时不签发。联调服务端已应用，提交为 `2672032`；其他部署需要应用此补丁并重构建 Multica 服务端。
2. **工具读取的运行说明进入蒸馏输入。** 修复前真实 OpenViking 归档中同时存在 `# Multica Agent Runtime` 和平台测试标记；该轮检查的抽取文件未出现这两个标记，仍无法保证蒸馏不会学习说明。现在对嵌套工具输入/输出、运行错误、可选 thinking、智能体评论与聊天回复清理已识别的运行说明；保留成员原始输入及其他业务字段。修复后通过真实平台文件读取诊断验证归档与抽取。
3. **skill 安装与运行挂载是两个步骤。** 插件安装后，工作区中已有记忆 skill，但新智能体仍需绑定它。已在安装文档明确说明；正式复测在创建智能体时绑定安装产生的 skill，实际执行记录显示使用了原生 skill 工具。

此前 `e2e/real-stack/` 的 12/12 验证使用真实服务，但任务转写及工具请求由 daemon 协议样例驱动，并未启动智能体 CLI。已修正文档与旧报告的描述。新增 [`e2e/real-agent/`](../e2e/real-agent/README.md) 用于实际智能体执行。
