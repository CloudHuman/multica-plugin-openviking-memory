# 真实模型 A/B：归档前去掉成员消息里的执行指令 — 2026-10-08 UTC

> **决定（2026-10-08）**：按本报告的结果，`archiveDropRunControls` 改为默认开启，设 `OVMEM_ARCHIVE_DROP_RUN_CONTROLS=0` 可恢复按原文归档。quality 套件同时改为遇到内容失败时记失败、继续跑（见 README 变更记录）。

用户的问题是：原生抽取有时把“回复前先调用 memory-recall”这类执行指令写进记忆，要不要在归档前就去掉成员消息里这些固定的执行指令。决定前先做 A/B 对比。

为此在 `6bb923e` 加了实验开关 `archiveDropRunControls`，默认关闭（环境变量 `OVMEM_ARCHIVE_DROP_RUN_CONTROLS`）。开启后：

- **去掉的**：成员消息和任务描述里已知的一次性执行指令，按句去掉，用的是召回过滤的同一套规则。
  - 例子：“请先调用 memory-recall，按实际证据回复”“不要修改代码，不要主动记录记忆”“按平台流程提交简短回复”。
  - 范围：议题描述、成员评论、私聊消息、运行中追加的要求。
- **保留的**：
  - 业务事实、“以后/一律”这类长期约定；
  - 智能体自己说的话；
  - 工具调用和结果；
  - 检索结论句，例如“历史检索为空不影响确认”，它不属于这个开关。

运行方式：

- **两组**：A 组按原文归档（off），B 组开启开关（on）。都用 OV 原生抽取，不配工作区规则。
- **轮次**：quality 套件，off 与 on 交替各 3 轮，使用真实 `OPENROUTER_API_KEY`。
- **环境**与上一轮[工作区规则验证](real-agent-2026-10-08-config-rules.md)相同：
  - 推荐的 OV 配置，存储目录为新建的空目录；
  - 补丁版 Multica、OpenCode 1.17.7；
  - 执行模型 `gpt-5.4-mini`，抽取模型 `glm-5.3-flash`；
  - 抽取调用经记录代理，代理不记录请求头。

## 结论

1. **关闭时，3 轮都有抽取因为“不要主动记录记忆”放弃写入**：
   - **off-r1、off-r2**：种子任务的抽取直接回答“用户明确指示不要记录记忆，因此不做任何写入操作”，或“用户在任务中明确要求「不要主动记录记忆」……不做任何记忆写入”，然后空提交。
     - 结果只剩智能体评论抽出的事件，没有实体卡，也没有偏好。
     - 第一次共享晋升没有可晋升的内容，套件在第 4 项后停止。
   - **off-r3**：
     - 种子任务正常抽出实体卡。
     - B 的查询任务以同样理由不写；那次本来也没有新事实。
     - 私聊那次抽取空提交，周报版式没有被抽取，套件停在私聊检查（10/11）。
2. **开启时 0 次这样的放弃**：
   - **on-r1、on-r3**：跑完全部 15 项，各 14/15。私聊版式两次都抽取并在新会话召回，偏好里只有版式和“仅用于私聊”。
   - **on-r2**：抽取没有拒绝，但种子任务只写了事件、没写实体卡。这是原生抽取另一种不稳定的表现，套件同样在第一次晋升处停止。
3. **开启没有看到事实或偏好的损失**：
   - 事实保真两组都是 3/3；
   - 持久偏好被保留：off 1/3，on 2/3；
   - 跑到这一步的 B 共享召回和预算更新检查全部通过。
4. **两次失败（on-r1、on-r3）都是同一句检索结论，不是执行指令**：
   - 成员原文“本次成员确认是直接证据，历史检索为空不影响确认”被写进了任务空间的实体卡，例如“当时记忆检索为空不影响确认效力”。开关有意不处理这类句子。
   - 共享晋升把这句去掉了：4 次晋升都是 `cleaned: ['retrieval-outcome']`。B 从共享空间取回的卡里，这一行只剩“上述约定以任务正文的成员确认为直接证据。”
   - 这也是“清理后晋升”和“检索为空”识别第一次在真实运行里触发并起作用。
5. **开关没覆盖到的地方**：
   - 智能体用 `multica issue get` 读议题时，工具结果里仍是原始描述，所以开启后种子任务的归档里还有 1–2 处执行指令。
   - 抽取模型没有因此拒绝（开启时 0 次），说明拒绝主要来自用户消息里的这句话。
   - 私聊没有这类工具读取，开启后私聊归档里一处都没有。
6. **样本很小**：
   - 每组只有 3 轮。
   - 之前 8 轮都按原文归档（10-02 共 6 轮、10-08 共 2 轮，其中 4 轮是原生抽取），抽取回答里都没有引用这句指令的放弃；只有 10-02 native 第 3 轮的私聊同样空提交。
   - 这一轮关闭组 3 轮都出现了，说明这一行为在不同时段差异很大。
   - 结论方向一致，但比例不能外推。
7. **花费**：
   - 关闭组 $0.153，其中两轮提前停止；
   - 开启组 $0.345；
   - 共 $0.497。

## 5. 对决定的含义

- **支持开启的证据**：
  - 关闭组 3 轮都有抽取因成员的“不要主动记录记忆”放弃写入，丢掉了种子任务的卡片或私聊版式；开启组 0 次。
  - 开启后没有看到事实或偏好的损失。
- **代价**：归档里的成员原文少了这些句子。只去已知的固定执行指令句，其余内容和工具结果原样保留。开关可以随时关掉，已归档的记录不受影响。
- **还可以考虑的后续**（都需要另行验证）：
  1. 把检索结论句（“历史检索为空不影响确认”）也纳入开关。本轮开启组的两次失败都来自它，目前只能在晋升和召回时兜底。
  2. 改进 quality 套件：第一次晋升没有内容时记一项失败、继续往下跑，避免一次不稳定的抽取遮住后面私聊等检查的结果。这样以后的对比能拿到更完整的数据。
