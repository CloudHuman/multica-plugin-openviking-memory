# 多智能体与 Multica 入口实测 — 2026-10-01 UTC

使用正式 Multica daemon、OpenCode 1.17.7、真实 OpenViking 0.4.22 和真实模型执行；任务转写、工具调用、交接评论和最终回复由智能体产生。执行模型为 `openrouter/openai/gpt-5.4-mini`，OpenViking 抽取仍使用 `z-ai/glm-5.3-flash`，向量与重排保持原有 Qwen3 配置。

七类记忆范围均有真实样例。逐项修复、恢复与核对后，30 项检查通过；这不是一次无故障的全绿运行。26 个记录中的真实任务有 25 个完成，1 个在已正确拒绝越界读取后因 `Missing Authentication header` 未完成最终交付。运行中追加输入另有明确的运行时限制。原失败检查、停止原因、验证器纠正和重驱过程保留在[机器记录](real-agent-matrix-2026-10-01.json)。

修复并提交的行为：

- 现代委派以 agent-authored mention 评论触发；插件原先只识别旧 handoff 输入，遗漏通道归档。现在仅采纳关联发送方的评论，并过滤其中识别到的平台运行说明。
- 配套任务读取 API 原先在快速创建关联 issue 后改判为普通 issue，改变归档范围并遗漏原提示。新增第三个 Multica 补丁保留原类型与成员提示；PostgreSQL 回归先失败、修复后通过，真实运行复测归档到 run 空间。
- 共享晋升原先提交后即记录为已处理，抽取失败没有监视或重驱。本轮真实模型错误复现了不可检索状态。现在先持久化入队，复用归档监视、重启恢复与新会话重驱；旧失败归档可以在同工作区共享范围内验证失败后恢复，原始失败文件保留。
- 共享晋升达到单个空间限额时原先提前结束整批，现继续处理其他来源。并发晋升串行选择来源；队列受理及回执写入失败均有幂等恢复回归。
- skill 明确本次成员确认是有效证据、检索失败不能说成没有记忆；协作/私聊/委派/共享条目的 `content` 已由插件读取，直接核对并引用，避免用仅限自己公共空间的 `ov-read` 再次跨空间读取。

核验 28 份成功抽取对应的任务与委派归档，均没有已检查的平台运行标题和内部测试标记；48 个业务记忆文件也没有这两项及所检查的运行说明特征。内置 `identity.md` / `soul.md` 不计入业务蒸馏数量；前一份基本测试报告的 12 个文件中有 8 个内置文件，已更正计数说明。过滤仍依赖已识别格式，任意未标记的 skill 或平台说明尚未验证。

测试过程中保留了版本门禁和验证器问题的证据：CLI 原先固定为 `0.2.0-integration-patched`，被快速创建版本检查拒绝；取得真实 release tags 后按官方构建规则生成 `v0.6.0-7-g267203249`。成员 issue 列表没有 origin 字段，改为核对实际 task→issue 关联、创建者和绑定类型。webhook 匹配需排除缺失 ID；创建 issue 的自动化按其持久化 issue ID 核对任务。没有补写智能体转写或代替智能体调用记忆工具。

模型认证错误仍需关注：本轮智能体交付和多次 OpenViking 抽取出现 401，部分抽取经重驱恢复；共享恢复在 r2 会话完成，随后共享查询任务的归档又经一次重驱完成。错误原因未确定，成功复测不能证明认证稳定性已解决。早期 GLM 作为执行模型的试跑还出现过五分钟超时；主矩阵因此选择当前连接中确认可用的 GPT-5.4-mini，未改变 OpenViking 的模型配置。

插件回归 106/106；相关 Multica handler 回归、`go vet`、三个补丁的干净应用与包校验通过。服务端实际修复提交为 `cb3dbeeca`，插件实现提交为 `e9602f2`。矩阵在同一个隔离工作区分阶段继续；中途更新过已绑定 skill，时间和哈希记录在机器报告中。既有数值不会在查询任务中重新提供。

本轮验证服务端主要入口，尚未逐一操作 Web、桌面、移动客户端或外部聊天渠道；私聊测试使用一位真实成员与两名智能体，另两位成员之间的实际配对隔离未验证；其他智能体运行时也未在该矩阵中复验。测试使用合成业务内容，没有向外部渠道发送通知。

测试 daemon 已停止，原插件服务已恢复，API 与 Web 代理健康；两个智能体无排队或运行中任务，三个自动化已暂停且没有触发规则，测试抽取监视没有未完成项。详细转写与凭据仅保留在本地私有测试目录，报告不包含密钥。
